# Архитектура

Для разработчиков и проверяющих код: как устроен модуль, какие данные и как передаются, где что лежит в исходниках.

## Компоненты

```
 АРМ проверяющего                                         ПК локальной сети (каждый)
┌────────────────────────────────┐   TCP 50555          ┌────────────────────────────────┐
│ SkziControlPanel.exe (WinForms) │   запрос и ответ     │ SkziAgent.exe — служба Windows │
│ • список ПК, поиск агентов      │   подписаны          │ (LocalSystem, без окон)        │
│ • папки для поиска              │   HMAC-SHA256        │ • хранилища «Личное» всех      │
│ • параллельное сканирование     │ ───────────────────▶ │   пользователей и компьютера   │
│ • установка агентов (\\ПК\C$)   │ ◀─────────────────── │ • контейнеры КриптоПро         │
│ • просмотр БД, CSV              │   XML ScanResult     │ • файлы в папках из панели     │
│                                 │                      │ • КриптоПро CSP и лицензия     │
│                                 │   без агента:        └────────────────────────────────┘
│                                 │   \\ПК\C$ + удалённый реестр
└───────────────┬────────────────┘
                │ ADO.NET: создание БД и таблиц, upsert, места, отметка пропавших
                ▼
        ┌──────────────┐
        │ MSSQL         │ dbo.SkziCertificates, dbo.SkziCertificatesLocations
        └──────────────┘
```

- **Панель** — единственная точка записи в БД. Агенты к БД не подключаются и не хранят у себя учётных данных.
- **Агент** только отвечает на подписанные запросы: сам никуда не подключается и ничего не отправляет по своей инициативе.
- **Общий код** (`src/Common`) подключается в оба проекта ссылками на файлы. Каждый `.exe` самодостаточен.

## Поток данных при сканировании

1. Оператор нажимает «Сканировать». `ScanCoordinator` опрашивает ПК параллельно (по умолчанию 8 одновременно, таймаут 180 с).
2. Для каждого ПК панель подключается к агенту, получает приветствие с одноразовым числом (nonce), отправляет подписанный запрос `Scan` с папками для поиска.
3. Агент выполняет `CertificateCollector.Scan`: хранилища → контейнеры КриптоПро → файлы. Сертификаты объединяются по отпечатку; у записи копится список источников («Файл: …», «Личное хранилище …», «Контейнер КриптоПро: …»).
4. Агент разбирает каждый сертификат (`CertificateParser`) и отвечает подписанным XML `ScanResult`: сертификаты, сведения о КриптоПро на ПК, область сканирования, предупреждения, статистика.
5. Панель показывает результат и (если включено) пишет его в MSSQL одной транзакцией на ПК.

Без агента панель делает то же сама: файлы и профили читаются через `\\ПК\C$`, хранилища и сведения о КриптоПро — через удалённый реестр. «Этот ПК» — тот же `CertificateCollector` локально.

## Протокол «панель ↔ агент»

TCP, кадр = 4 байта длины (big-endian) + полезная нагрузка UTF-8, не больше 64 МБ.

```
агент  → панель:  SKZI-AGENT/1.0|<nonce Base64, 32 байта>|<имя ПК>|<версия>
панель → агент:   <HMAC Base64>\n<XML AgentRequest>     HMAC-SHA256(ключ, nonce + 0x01 + XML)
агент  → панель:  <HMAC Base64>\n<XML AgentResponse>    HMAC-SHA256(ключ, nonce + 0x02 + XML)
```

- **Ключ по сети не передаётся.** Подпись защищает запрос и ответ от подмены.
- **Nonce** выдаёт агент на каждое соединение, поэтому перехваченный запрос нельзя воспроизвести.
- Запрос содержит время формирования (UTC). Агент отклоняет запросы старше 10 минут.
- Байт направления (0x01 / 0x02) не позволяет выдать ответ за запрос.
- `AllowedClients` ограничивает адреса панелей.
- Команды: `Ping` (проверка связи и ключа — «Агент на ПК» → «Проверить связь») и `Scan`. Поиск агентов в сети читает только приветствие агента, ключ для этого не нужен.

Исходники: `src/Common/Network/AgentProtocol.cs`, `AgentClient.cs`; сервер — `src/SkziAgent/AgentServer.cs`.

## Что и откуда собирается

| Источник | Как читается | Модуль |
|---|---|---|
| Хранилище «Личное» вошедших пользователей | Реестр `HKEY_USERS\<SID>`, хранилище `My` | `CertificateStoreScanner` |
| Хранилище «Личное» не вошедших пользователей | Файловое хранилище в профиле (`AppData\Roaming\Microsoft\SystemCertificates\My\Certificates`) | `CertificateStoreScanner` |
| Хранилище «Личное» компьютера | Хранилище `My` компьютера (`LocalMachine`) | `CertificateStoreScanner` |
| Ключевые контейнеры КриптоПро (реестр, флешки, токены) | CryptoAPI: перечисление контейнеров и `KP_CERTIFICATE`, **без PIN-кода и доступа к ключам** | `CryptoProContainerScanner` |
| Файлы в папках | DER, PEM (в т.ч. цепочки), Base64 без заголовков, PKCS#7, PKCS#12 (только с паролем оператора) | `DirectoryScanner`, `CertificateFileLoader` |
| КриптоПро CSP на ПК | Реестр установленных программ, версия DLL криптопровайдера, лицензия (`cpconfig -license -view`; для пробной — 90 дней от установки) | `CryptoProDetector` |

### Разбор сертификата

`CertificateParser` использует собственный DER-парсер (`Asn1Node`) поверх `X509Certificate2`:

- **владелец** — ФИО из `SN` + `G`, иначе `CN`; ИНН, СНИЛС, ОГРН, организация, должность;
- **удостоверяющий центр** — полное имя издателя (`CN=…, O=…, C=RU`);
- **встроенная лицензия КриптоПро** — расширение «Ограниченная лицензия КРИПТО-ПРО», OID `1.2.643.2.2.49.2`. Версия определяется по серийному номеру лицензии (`5050…` → 5.0, `4040…` → 4.0), иначе по тексту вида «CSP 5.0», иначе «не определена». Ключ лицензии маскируется в БД и журналах;
- алгоритмы ГОСТ, срок действия, отпечаток, наличие закрытого ключа.

## База данных

Структура: [sql/create_table.sql](../sql/create_table.sql). Программа создаёт её сама (`CertificateRepository.EnsureTableExists`) и дополняет столбцами существующую таблицу.

### `dbo.SkziCertificates` — одна строка на сертификат

| Столбец | Тип | Требование кейса |
|---|---|---|
| `SerialNumber` | NVARCHAR(128), **UNIQUE** | 4.1 серийный номер; 4.2 без дублей |
| `InsertedAt` | DATETIME2(3) | 4.1 дата и время внесения |
| `UpdatedAt` | DATETIME2(3) | 4.1 дата и время обновления (= `InsertedAt` при первой записи) |
| `OwnerName` | NVARCHAR(512) | 4.1 имя владельца |
| `CertificationAuthority` | NVARCHAR(1000) | 4.1 удостоверяющий центр |
| `CryptoProLicenseVersion` | NVARCHAR(64) | 4.1 версия, если это лицензия КриптоПро |
| `HasEmbeddedCryptoProLicense` | BIT | 4.1 встроена ли лицензия |
| `IsMissing`, `MissingSince`, `LastSeenAt` | BIT, DATETIME2 | Сверх задания: пометка пропавших |
| `InstalledCryptoProVersion`, `…LicenseSerial`, `…LicenseValidity` | NVARCHAR | Сверх задания: КриптоПро и лицензия на ПК |
| Отпечаток, срок, ИНН, СНИЛС, ОГРН, организация, должность, DN, алгоритм, ПК, источник, способ сканирования | — | Расширенные сведения |

### `dbo.SkziCertificatesLocations` — где найден сертификат

Связь «сертификат — ПК — источник» (файл, хранилище, контейнер) с датами первого и последнего обнаружения и своей отметкой «пропал». Уникальность — по (серийный номер, ПК, SHA-256 источника).

### Запись без дублей

Результат одного ПК пишется одной транзакцией с одним временем `@Now = SYSDATETIME()` сервера БД:

1. Для каждого сертификата: `UPDATE … WITH (UPDLOCK, SERIALIZABLE) WHERE SerialNumber = @Serial`; если строк 0 — `INSERT`. Блокировка диапазона ключа исключает гонку при параллельной записи с нескольких ПК, уникальный индекс — последняя линия защиты.
2. То же для мест в `SkziCertificatesLocations`.
3. Места этого ПК, которые **входили в область сканирования**, но где сертификат не найден, помечаются `IsMissing = 1`. Сертификат помечается пропавшим, когда у него не осталось ни одного «живого» места. Найден снова — отметка снимается.

Область сканирования (`ScanResult.ScannedDirectories`, расширения, флажки хранилищ и контейнеров) передаётся вместе с результатом. По ней `CertificateSources.IsCoveredByScan` решает, проверялось ли место в этот раз.

## Журнал

`src/Common/Logging/Logger.cs`:

- формат из задания с уровнем: `дд.ММ.гг чч:мм:сс.мсс - [INFO|WARN|ERROR] текст`;
- файл `logs\<Программа>_ГГГГ-ММ-ДД.log`: новый каждые сутки и при превышении размера; старые удаляются по сроку хранения;
- все исключения пишутся со стеком и вложенными исключениями; необработанные перехватываются (`AppDomain.UnhandledException`, `Application.ThreadException`, `TaskScheduler.UnobservedTaskException`);
- запись потокобезопасна, журнал не прерывает работу программы при ошибке записи.

## Безопасность

| Угроза | Мера |
|---|---|
| Чужая панель опрашивает агенты | HMAC-SHA256 общим ключом, `AllowedClients` |
| Перехват и повтор запроса | Nonce агента на каждое соединение, отметка времени запроса |
| Подмена ответа агента | Ответ подписан тем же ключом с другим байтом направления |
| Утечка паролей из конфигурации | Пароль SQL и пароли `.p12` под DPAPI текущего пользователя; агентам не передаются |
| SQL-инъекции | Все запросы параметризованы; имя таблицы проверяется по белому списку символов |
| Доступ к закрытым ключам | Агент передаёт только открытые части. Контейнеры КриптоПро читаются штатно (`KP_CERTIFICATE`) без PIN и без файлов ключей; `.p12` открываются только паролем оператора |
| Пользователь останавливает агент | Дескриптор безопасности службы: обычный пользователь её не видит и не управляет ею; администратор и система — полный доступ, аудит обращений |
| Утечка данных наружу | Нет обращений к интернету и облаку; обмен только внутри ЛВС |

Сознательно **не делается**: сокрытие процесса из диспетчера задач, маскировка под системный процесс, обход антивируса.

## Автотесты

`build.cmd test` — 25 тестов без внешних зависимостей и 3 теста MSSQL (если задан `SKZI_TEST_SQL`):

- журнал: формат, уровни, ротация, удаление старых файлов;
- ASN.1, форматы файлов, разбор полей, файлы куратора, PKCS#12 с паролем и без;
- встроенная лицензия КриптоПро и срок лицензии CSP на ПК, контейнеры без CSP;
- маски путей, безагентные пути, правило «что входило в область сканирования»;
- полное сканирование тестовой папки, конфигурация, сериализация;
- протокол агента: верный и неверный ключ, поиск агентов, поиск только в папках панели;
- режимы запуска агента и настоящий `SkziAgent.exe --background`; одинаковые параметры службы при локальной установке и из панели;
- защита имени таблицы от SQL-инъекций, диапазоны IP;
- MSSQL: создание и дополнение таблиц, upsert без дублей, пропавшие и вернувшиеся сертификаты, места.
