# Установка и настройка

Для администратора, который ставит модуль: панель управления на АРМ проверяющего, агенты на ПК сети, базу данных MSSQL.

Работа с панелью описана в [РУКОВОДСТВО_ПОЛЬЗОВАТЕЛЯ.md](РУКОВОДСТВО_ПОЛЬЗОВАТЕЛЯ.md).

---

## Состав

| Компонент | Где работает | Права |
|---|---|---|
| `SkziControlPanel.exe` — панель управления | АРМ проверяющего | Запуск — только от имени администратора (запрос UAC). Для установки агентов по сети — администратор на целевых ПК |
| `SkziAgent.exe` — агент | Каждый сканируемый ПК, служба Windows | Установка — администратор. Служба работает от «Системы» |
| Microsoft SQL Server | АРМ проверяющего или сервер ЛВС | Право создавать БД и таблицы, либо готовая БД |

Оба `.exe` самодостаточны: им не нужны DLL рядом и Visual Studio.

## Требования

- Windows 10 или новее (требование кейса; проверено на Windows 11).
- .NET Framework 4.5 или новее. В Windows 10/11 он встроен.
- Microsoft SQL Server любого выпуска: Express, Developer, Standard или LocalDB. Проверено на SQL Server 2022 LocalDB.
- Сеть: панель подключается к агентам по TCP **50555**. Правило брандмауэра «SKZI Agent» агент создаёт сам.
- Интернет не нужен: все данные остаются внутри локальной сети.

## Файлы релиза

Релиз собирается командой `release.cmd` (см. ниже) и лежит в `dist\v<версия>\`. Эти же файлы прикладываются к релизу на GitHub.

| Файл | Что это |
|---|---|
| `SkziControlPanel-Setup-<версия>.exe` | Установщик панели для текущего пользователя. Права администратора не нужны |
| `SkziAgent-Setup-<версия>.exe` | Установщик агента на ПК: служба Windows, запрашивает права администратора |
| `SkziModule-<версия>-portable.zip` | Без установки: оба `.exe`, примеры конфигураций, SQL-скрипт, документация |
| `SHA256SUMS.txt` | Контрольные суммы — сверьте перед установкой |

Установщики не подписаны цифровой подписью. При первом запуске Windows SmartScreen может показать «Windows защитила ваш компьютер»: нажмите «Подробнее» → «Выполнить в любом случае». Перед этим сверьте SHA-256:

```powershell
Get-FileHash .\SkziAgent-Setup-1.0.0.exe -Algorithm SHA256
```

## 1. База данных

Ничего создавать заранее не нужно. Панель сама создаёт базу (если включено «Создавать базу данных, если её нет»), таблицу сертификатов и таблицу мест «сертификат — ПК». Если таблица уже есть, добавляются недостающие столбцы.

1. Установите SQL Server, если его нет. Для одного АРМ подойдёт SQL Server Express или LocalDB.
2. В панели: «Настройки» → «Сервер MSSQL». Если поле пустое, панель при запуске сама подставит SQL Server, найденный на этом ПК.
3. Выберите проверку подлинности Windows или логин и пароль SQL. Пароль хранится зашифрованным (DPAPI).
4. «Проверить подключение» → «Сохранить настройки».

Справочная структура таблиц — [sql/create_table.sql](../sql/create_table.sql). Агентам доступ к БД не нужен: в БД пишет только панель.

## 2. Панель управления

**Установщик.** Запустите `SkziControlPanel-Setup-<версия>.exe`. Панель ставится в `%LOCALAPPDATA%\Programs\SkziControlPanel` и создаёт ярлык «СКЗИ — панель управления» в меню «Пуск» и на рабочем столе. В «Установленных приложениях» появится запись для удаления.

Почему в профиль пользователя: панель хранит конфигурацию и журналы рядом с `.exe`, а пароли шифрует ключом текущего пользователя. Права администратора для установки не нужны, но **запускается панель только от имени администратора**: при открытии Windows запросит права (UAC). Так рядовой сотрудник не сможет сканировать сеть, даже если знает общий ключ.

Повторный запуск установщика обновляет программу. Настройки (`panel.config.xml`: список ПК, папки, пароли) сохраняются.

**Без установки.** Распакуйте `SkziModule-<версия>-portable.zip` в любую папку, где у пользователя есть право записи, и запустите `SkziControlPanel.exe`.

`SkziAgent.exe` должен лежать рядом с панелью: из него панель устанавливает агенты по сети. Установщик и архив кладут его автоматически.

## 3. Общий ключ

Панель и агенты подписывают запросы общим ключом (HMAC-SHA256). Ключ по умолчанию `RedFlag-SKZI-ChangeMe` годится только для проверки.

1. Панель: «Настройки» → «Общий ключ» → **«Сгенерировать новый»** → «Сохранить настройки».
2. Установите или обновите агенты **из панели**: она запишет на ПК `agent.config.xml` с новым ключом.

Если агенты ставятся установщиком или вручную, впишите тот же ключ в `SharedKey` файла `agent.config.xml` в папке агента и перезапустите службу. Другой вариант — задать ключ в `config\agent.config.xml` и `config\panel.config.xml` до сборки релиза.

## 4. Агенты на ПК сети

Выберите любой способ.

### А. Из панели по сети (удобнее всего)

Выделите ПК → **«Агент на ПК» → «Установить / обновить агент на выбранных ПК»**.

Панель копирует агент в `C:\Program Files\SkziAgent` через `\\ПК\C$`, пишет конфигурацию со своим ключом и папками, регистрирует службу через `sc \\ПК` и запускает её.

Нужно:
- панель запущена от учётной записи, которая является администратором на целевых ПК (например, доменной);
- на ПК доступны административные ресурсы (`C$`, `ADMIN$`) и удалённое управление службами — в домене это обычно так.

Если АРМ не в домене, запустите панель от доменной учётной записи:
```bat
runas /netonly /user:ДОМЕН\администратор "%LOCALAPPDATA%\Programs\SkziControlPanel\SkziControlPanel.exe"
```

### Б. Установщиком на самом ПК

Запустите `SkziAgent-Setup-<версия>.exe` и подтвердите запрос прав (UAC). Установщик:
1. копирует агент в `C:\Program Files\SkziAgent`;
2. регистрирует службу «СКЗИ: агент сбора данных о сертификатах» — автозапуск, перезапуск при сбое, от имени «Система»;
3. ограничивает доступ к службе (обычный пользователь её не видит) и открывает порт 50555;
4. запускает службу.

Повторный запуск обновляет агент. `agent.config.xml` при этом сохраняется; заменить его на файл из установщика можно параметром `/resetconfig`.

### В. Массовая установка (GPO, SCCM, сценарии)

Тихий режим без окон:

```bat
SkziAgent-Setup-1.0.0.exe /Q
```

Для групповой политики: «Конфигурация компьютера» → «Политики» → «Конфигурация Windows» → «Сценарии» → «Автозагрузка». Укажите путь к установщику на общем ресурсе и параметр `/Q`. Сценарии автозагрузки выполняются от «Системы», поэтому запроса прав не будет.

Самораспаковывающийся установщик всегда завершается с кодом 0 — так устроен IExpress. Итог установки на каждом ПК дописывается в `C:\Program Files\SkziAgent\logs\setup.log`. Подробности — в журнале агента в той же папке. Проверить, что агенты работают, удобнее всего из панели: «Найти агенты в сети…».

После массовой установки обновите агенты из панели, чтобы они получили ваш ключ (см. п. 3). Или соберите релиз с вашим ключом в `config\agent.config.xml`.

### Г. Вручную

Скопируйте `SkziAgent.exe` и `agent.config.xml` в папку на ПК и выполните из командной строки администратора:

```bat
SkziAgent.exe --install
```

Двойной щелчок по `SkziAgent.exe` делает то же самое: запрашивает права через UAC, ставит службу и сообщает результат окном. Консоль не показывается.

### Если прав администратора на ПК нет

`SkziAgent.exe --background` запускает агент в фоне без окна и без службы — до выхода из системы. Он видит только сертификаты текущего пользователя и указанные папки. Остановить: `SkziAgent.exe --stop`.

### Проверка

```bat
"C:\Program Files\SkziAgent\SkziAgent.exe" --status
```

Покажет состояние службы, фонового режима и ответ на порту. Из панели: «Агент на ПК» → «Проверить связь с агентом».

### Скрытность агента

Агент работает службой без окон и значков. Обычный пользователь не видит службу в «Службах» и `sc query` и не может её остановить: так настроен дескриптор безопасности службы. Администратор и система видят службу и управляют ею, обращения к службе пишутся в журнал аудита Windows. Процесс агента не скрывается из диспетчера задач и не маскируется — это сознательное решение: средство учёта СКЗИ не должно вести себя как вредоносная программа.

## Удаление

| Что | Как |
|---|---|
| Агент на ПК | Из панели: «Агент на ПК» → «Удалить агент с выбранных ПК». На самом ПК: `C:\Program Files\SkziAgent\uninstall-agent.cmd` (от администратора, `/quiet` — без окон) или `SkziAgent.exe --uninstall` |
| Панель | «Параметры» → «Приложения» → «Модуль сбора данных о СКЗИ — панель управления» → «Удалить». Агенты и БД не затрагиваются |
| Данные | Таблицы `dbo.SkziCertificates` и `dbo.SkziCertificatesLocations` удаляются средствами SQL Server |

## Конфигурация агента (`agent.config.xml`)

Файл лежит рядом с `SkziAgent.exe`. При установке из панели он формируется из настроек панели.

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `ListenPort` | 50555 | TCP-порт для запросов панели |
| `SharedKey` | `RedFlag-SKZI-ChangeMe` | Общий ключ; должен совпадать с панелью. **Смените** |
| `AllowedClients` | пусто | IP или имена панелей, которым можно обращаться. Пусто — любые с верным ключом |
| `ScanDirectories` | `C:\Certs`, `C:\Users\*\Desktop`, `Documents`, `Downloads` | Папки поиска, если панель не прислала свои |
| `CertificateFileExtensions` | `.cer;.crt;.der;.pem;.cert;.p7b;.p7c;.p12;.pfx` | Какие файлы считать сертификатами |
| `ScanCertificateStores` | true | Хранилища «Личное» всех пользователей и компьютера |
| `ScanCryptoProContainers` | true | Ключевые контейнеры КриптоПро (через CryptoAPI, без PIN) |
| `MaxCertificateFileSizeKb` | 2048 | Более крупные файлы пропускаются |
| `AcceptDirectoriesFromPanel` | true | Принимать папки от панели |
| `LogDirectory`, `LogRetentionDays`, `LogMaxFileSizeMb` | `logs`, 30, 10 | Журнал |
| `DatabaseConnectionString`, `DatabaseTableName` | пусто, `dbo.SkziCertificates` | Только для автономного `--scan --db` |

## Параметры командной строки агента

```
SkziAgent.exe                     (двойной щелчок) установить службу и работать в фоне без окна
SkziAgent.exe --install           установить службу, открыть порт, запустить (администратор)
SkziAgent.exe --uninstall         удалить службу и правило брандмауэра
SkziAgent.exe --background        работать в фоне без службы (нет прав администратора)
SkziAgent.exe --stop              остановить агент, запущенный через --background
SkziAgent.exe --status            служба, фоновый режим, ответ на порту
SkziAgent.exe --console           агент в окне консоли до Ctrl+C (отладка)
SkziAgent.exe --scan [--dir папка]... [--out файл.xml] [--db]
                                  разово просканировать этот ПК: вывести, сохранить в XML, записать в MSSQL
SkziAgent.exe --config путь       другой файл конфигурации
```

## Сборка из исходников и выпуск релиза

Нужен только .NET Framework 4.x (компилятор `csc.exe` входит в него). Visual Studio не требуется, но проект открывается в ней (`SkziCollector.sln`).

```bat
build.cmd                 :: сборка в bin\
build.cmd test            :: сборка + автотесты
release.cmd               :: сборка + тесты + установщики, ZIP и SHA-256 в dist\v<версия>\
release.cmd -SkipTests    :: то же без тестов
```

Тесты MSSQL запускаются, если задана строка подключения:

```bat
set SKZI_TEST_SQL=Server=(localdb)\MSSQLLocalDB;Database=SkziTest;Integrated Security=true
```

Строгая проверка совместимости с API .NET 4.5: укажите в `SKZI_NET45_REFS` папку со справочными сборками .NET 4.5 (NuGet-пакет `Microsoft.NETFramework.ReferenceAssemblies.net45`, папка `build\.NETFramework\v4.5`).

Версия берётся из `AssemblyVersion` в `src\SkziControlPanel\Properties\AssemblyInfo.cs` (и агента). Описание выпуска — из раздела этой версии в [CHANGELOG.md](../CHANGELOG.md).

Установщики — самораспаковывающиеся архивы штатного IExpress Windows: распаковывают файлы во временную папку и запускают `install.cmd`. Сценарии установки лежат в [installer/](../installer). В установщики попадают примеры конфигураций из `config\`, а не рабочие файлы из `bin\`, где могут быть ваши пароли и список ПК.

## Если что-то не работает

| Признак | Причина и решение |
|---|---|
| Агент не отвечает | `SkziAgent.exe --status` на ПК. Служба остановлена — `sc start SkziAgent` (администратор). Порт закрыт сторонним брандмауэром — откройте TCP 50555 |
| «Неверный ключ» | Ключ в `agent.config.xml` отличается от панели. Обновите агент из панели |
| Запрос отклонён по адресу | Адрес панели не входит в `AllowedClients` агента |
| Установка из панели: «Отказано в доступе» | Нет прав администратора на ПК или закрыт `\\ПК\C$`. Запустите панель от доменного администратора (`runas /netonly`) |
| Служба не видна в «Службах» | Так задумано для обычных пользователей. Откройте «Службы» от имени администратора |
| Ошибка подключения к SQL Server | Проверьте имя экземпляра, что служба SQL Server запущена, и права учётной записи. Для LocalDB: `(localdb)\MSSQLLocalDB` |

Журналы: панель — `logs` рядом с `SkziControlPanel.exe`, агент — `C:\Program Files\SkziAgent\logs`.
