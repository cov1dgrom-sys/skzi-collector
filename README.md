# Модуль сбора данных о СКЗИ

Кейс №03 «ГРЧЦ», Всероссийский хакатон связи 2026. Команда **Red Flag**.

Программа находит на компьютерах локальной сети личные сертификаты и установленный КриптоПро CSP. Из каждого сертификата она извлекает серийный номер, владельца, удостоверяющий центр и сведения о встроенной лицензии КриптоПро. Результаты записываются в таблицу MSSQL без дублей. Сертификаты, которые пропали с ПК, помечаются.

| Файл | Назначение |
|---|---|
| `SkziControlPanel.exe` | Панель управления (WinForms). Список ПК, запуск сканирования, просмотр результатов и таблицы БД, установка агентов, настройки |
| `SkziAgent.exe` | Агент на сканируемом ПК. Работает в фоне и не показывает окон: служба Windows, которая запускается вместе с Windows. По подписанному запросу панели сканирует свой ПК и возвращает результат |
| `SkziTests.exe` | Автотесты |

Требования к среде из задания выполнены: C#, **.NET Framework 4.5** (API 4.5, синтаксис C# 5), MSSQL, `.exe` под Windows 10.

## Быстрый старт

```bat
build.cmd            :: сборка в bin\ (нужен только .NET Framework 4.x, Visual Studio не требуется)
build.cmd test       :: сборка + автотесты
release.cmd          :: сборка + тесты + установщики, ZIP и SHA-256 в dist\v<версия>\
```

Проект открывается и в Visual Studio: `SkziCollector.sln`.

**Демонстрация на одном ПК:**
1. Запустите `bin\SkziControlPanel.exe` и подтвердите запрос прав администратора: панель работает только от имени администратора. Если в конфигурации сервер MSSQL не указан, панель сама подставит SQL Server, найденный на этом ПК (Express, Developer или LocalDB). Проверить подключение можно на вкладке «Настройки».
2. На вкладке «Сканирование ПК» нажмите **«Папки для поиска…»** и добавьте `samples\certs` и `samples\curator`.
3. Нажмите **«Этот ПК»**. Найдётся 8 сертификатов: 6 наших тестовых и 2 от куратора. Истёкший подсвечен красным, три — со встроенной лицензией КриптоПро. Файлы `.p12` куратора закрыты паролем `changeit`: укажите его в «Настройки» → «Пароли для .p12/.pfx» — тогда они прочитаются с закрытым ключом; без пароля они попадут в «Предупреждения», а сертификаты возьмутся из `.cer`.
4. Вкладка «Сертификаты в БД» покажет таблицу. Повторное сканирование не добавит новых строк, а обновит «Дату и время обновления».
5. Удалите файл из папки и просканируйте ещё раз: строка станет серой с отметкой «Пропал». Двойной щелчок по строке покажет, на каких ПК и где найден сертификат.

**Сканирование ПК в сети:**
1. Установите агент одним из способов:
   - из панели: выделить ПК → «Агент на ПК» → «Установить / обновить агент»;
   - на самом ПК: двойной щелчок по `SkziAgent.exe` → «Да» в окне контроля учётных записей. Агент установится службой и сообщит об этом окном, консоль не показывается;
   - из командной строки администратора: `SkziAgent.exe --install`.

   После установки агент работает в фоне: окон нет, он запускается вместе с Windows, перезапускается при сбое и ждёт запросов панели. Увидеть его можно в «Службах» («СКЗИ: агент сбора данных о сертификатах») или командой `SkziAgent.exe --status`.
2. Добавьте ПК в список одним из способов: «+ Добавить ПК», «Импорт из файла…» или «Найти агенты в сети…» (поиск по диапазону `192.168.1.1-254` или `10.0.0.0/24`).
3. Нажмите «Сканировать все».

## Архитектура

```
 ┌───────────────────────────┐   TCP 50555, запрос и ответ    ┌──────────────────────────────┐
 │  SkziControlPanel.exe      │   подписаны HMAC-SHA256        │  SkziAgent.exe (служба)      │
 │  • список ПК, поиск агентов│ ─────────────────────────────▶ │  • хранилища «Личное» всех   │
 │  • папки для поиска        │ ◀───────────────────────────── │    пользователей + компьютера│
 │  • параллельное            │      XML: ScanResult           │  • контейнеры КриптоПро      │
 │    сканирование            │                                │  • файлы в папках из панели  │
 │  • установка агентов       │   без агента: \\ПК\C$ +        │  • КриптоПро CSP и лицензия  │
 │  • просмотр БД, CSV        │   удалённый реестр             └──────────────────────────────┘
 └────────────┬──────────────┘
              │ ADO.NET: создание БД/таблиц, upsert по серийному номеру, отметка пропавших
              ▼
        ┌───────────┐
        │  MSSQL    │  dbo.SkziCertificates + dbo.SkziCertificatesLocations
        └───────────┘    (на ПК проверяющего)
```

Код агента и панели — общий (`src/Common`), подключается в оба проекта ссылками на файлы. Поэтому каждый `.exe` самодостаточен и не требует DLL рядом.

| Модуль | Что делает |
|---|---|
| `Common/Logging/Logger.cs` | Журнал `дд.ММ.гг чч:мм:сс.мсс - [INFO] текст`, ротация по суткам и размеру, удаление старых файлов, перехват всех необработанных исключений |
| `Common/Configuration` | Чтение и запись XML-конфигурации (папки, маски, расширения, пароли PKCS#12 под DPAPI) |
| `Common/Certificates/Asn1Node.cs` | Собственный DER-парсер: OID, строки, вложенные структуры |
| `Common/Certificates/CertificateFileLoader.cs` | DER, PEM (в т.ч. цепочки), Base64 без заголовков, PKCS#7, PKCS#12 с паролем оператора, сертификаты из реестра |
| `Common/Certificates/CertificateParser.cs` | Владелец, ИНН, СНИЛС, ОГРН, УЦ, алгоритмы ГОСТ, встроенная лицензия КриптоПро |
| `Common/Scanning` | Обход папок, хранилища «Личное» (реестр и профили на диске), контейнеры КриптоПро, КриптоПро CSP и срок лицензии, правило «что входило в область сканирования» |
| `Common/Network` | Протокол агента: кадры, HMAC, nonce, XML |
| `Common/Database` | Создание БД и таблиц, добавление и расширение столбцов, upsert без дублей, места «сертификат — ПК», отметка пропавших, поиск SQL Server на этом ПК |

## Соответствие заданию

| Требование | Реализация |
|---|---|
| C# .NET Framework 4.5, MSSQL, `.exe` под Windows 10 | `build.cmd` собирает штатным `csc.exe`. Совместимость с API 4.5 проверена сборкой против справочных сборок .NET 4.5 (`SKZI_NET45_REFS`) |
| Журнал с датой и временем до мс, все исключения в журнал | `Logger`: формат как в примере плюс уровень (`[INFO]`, `[WARN]`, `[ERROR]`). Новый файл каждые сутки и при превышении размера, старые удаляются; папка, срок и размер настраиваются. Обработчики `AppDomain.UnhandledException`, `Application.ThreadException`, `TaskScheduler.UnobservedTaskException`. Пишутся стек и вложенные исключения |
| Сбор личных сертификатов на ПК | Хранилище «Личное» компьютера и **всех** пользователей: вошедших (`HKEY_USERS`) и не вошедших (файловое хранилище в профиле). Сертификаты из ключевых контейнеров КриптоПро (реестр, флешки, токены) |
| Версия КриптоПро на ПК | Реестр (установленные программы), версия DLL криптопровайдера; серийный номер лицензии (маскируется) и срок её действия (`cpconfig -license -view`, для пробной — 90 дней с установки) |
| Панель управления для сканирования ПК в сети | `SkziControlPanel.exe` |
| **1.** Чтение конфигурационного файла с директориями | `agent.config.xml` / `panel.config.xml`. Папки задаёт тот, кто собирает сертификаты: «Папки для поиска…» на вкладке сканирования, `--dir` у агента. Поддерживаются маски `C:\Users\*\Desktop` и `%переменные%` |
| **2.** Сканирование директорий и парсинг файлов | `DirectoryScanner`, `CertificateFileLoader`, `CertificateParser`. Недоступные папки и битые файлы не останавливают работу, а попадают в предупреждения |
| **3.** Сканирование указанных ПК и сбор данных со сканирования на них | Агент (служба) + протокол TCP. Резервный режим без агента. Параллельное сканирование ПК |
| **4.** Если таблицы нет — создать, есть — вносить | `EnsureTableExists`. Если таблица уже существует, недостающие столбцы добавляются |
| **4.1** Серийный номер, внесение, обновление, владелец, УЦ, версия лицензии, «встроена ли» | Столбцы `SerialNumber`, `InsertedAt`, `UpdatedAt`, `OwnerName`, `CertificationAuthority`, `CryptoProLicenseVersion`, `HasEmbeddedCryptoProLicense` |
| **4.2** Без дублей: существующую строку обновить | `UPDATE … WITH (UPDLOCK, SERIALIZABLE)`, затем `INSERT`, если строки нет. Дополнительно уникальный индекс по `SerialNumber`. Время одно на всё сканирование — время сервера БД |
| Оформление кода | Комментарий у каждой функции, осмысленные имена, пробелы вокруг операторов, табуляция |

**Встроенная лицензия КриптоПро** определяется по расширению сертификата «Ограниченная лицензия КРИПТО-ПРО» (OID `1.2.643.2.2.49.2`). Версия берётся:
- из серийного номера лицензии: `5050…` → 5.0, `4040…` → 4.0;
- если номера нет — из явного текста вида «CSP 5.0».

Если версию найти не удалось, пишется «не определена». Сам ключ лицензии в БД и журналах маскируется.

| Порт — в конфигурации | Порт агентов задаётся в `agent.config.xml` (`ListenPort`) и `panel.config.xml` (`AgentPort`), а не зашит в программу |
| Файлы `.p12/.pfx` | Читаются паролем, который задал оператор; пароли хранятся зашифрованными |

## Режимы сканирования

| Режим | Как работает | Что нужно |
|---|---|---|
| **Через агент** (рекомендуется) | Панель шлёт агенту подписанный запрос с папками для поиска, агент сканирует свой ПК и возвращает XML | Агент на ПК, открытый порт 50555 (правило брандмауэра создаётся автоматически) |
| **Без агента** | Файлы и профили читаются через `\\ПК\C$`, хранилища и КриптоПро — через удалённый реестр. Контейнеры КриптоПро и срок лицензии так не прочитать | Права администратора на ПК, служба «Удалённый реестр» |
| **Этот ПК** | Локальное сканирование из панели | — |
| **По расписанию** | `SkziControlPanel.exe --scan-all` сканирует все ПК из конфигурации без окна и пишет в БД | Планировщик заданий Windows, задание с наивысшими правами |

Параметры агента:

```
SkziAgent.exe                     (двойной щелчок) установить службу и работать в фоне без окна;
                                  права администратора запрашиваются через UAC
SkziAgent.exe --install           установить службу, открыть порт, запустить (администратор)
SkziAgent.exe --uninstall         удалить службу
SkziAgent.exe --background        работать в фоне без окна и без службы — если нет прав администратора
SkziAgent.exe --stop              остановить агент, запущенный через --background
SkziAgent.exe --status            работает ли агент: служба, фоновый режим, ответ на порту
SkziAgent.exe --console           агент в окне консоли до Ctrl+C (для отладки)
SkziAgent.exe --scan              разово просканировать этот ПК и вывести результат
SkziAgent.exe --scan --dir D:\Certs  ... искать файлы только в указанных папках (можно несколько --dir)
SkziAgent.exe --scan --out r.xml  ... и сохранить результат в XML
SkziAgent.exe --scan --db         ... и записать в MSSQL (DatabaseConnectionString в конфигурации)
SkziAgent.exe --config путь       другой файл конфигурации
```

**Как агент работает в фоне.** Основной режим — служба Windows от имени LocalSystem: окон нет, запускается вместе с Windows до входа пользователя, после сбоя перезапускается. Службе видны хранилища всех пользователей и контейнеры КриптоПро компьютера. Если прав администратора нет, `--background` запускает агент без окна до выхода из системы. Он видит только сертификаты текущего пользователя и папки, при первом запуске Windows может спросить разрешение на доступ к сети. Двойной щелчок не оставляет консоль на экране: агент перезапускает себя без окна, а результат показывает окном сообщения.

**Незаметность для рядового пользователя.** При установке службе задаётся ограниченный дескриптор безопасности (`sc sdset`): обычный пользователь не видит службу в «Службах» и `sc query` и не может её остановить. Администратор и система видят службу и полностью ею управляют; все обращения к службе пишутся в журнал аудита Windows. Это штатное разграничение доступа Windows, а не сокрытие процесса: агент не прячется из диспетчера задач, не маскируется под системный процесс и не уклоняется от антивируса — такие приёмы для средства учёта СКЗИ недопустимы.

## База данных

SQL Server стоит на ПК проверяющего. Подходит любой выпуск: Express, Developer, Standard или LocalDB (проверено на SQL Server 2022 LocalDB, `(localdb)\MSSQLLocalDB`). Если сервер в конфигурации не указан, панель сама находит экземпляры на этом ПК; они же есть в выпадающем списке «Сервер MSSQL» в настройках. Агентам доступ к БД не нужен. Программа не обращается к интернету и облачным сервисам: данные передаются только внутри локальной сети.

Таблица `dbo.SkziCertificates` (имя меняется в настройках) и таблица мест `dbo.SkziCertificatesLocations` создаются автоматически. Справочный скрипт: [sql/create_table.sql](sql/create_table.sql). У столбцов есть русские описания (`MS_Description`), они видны в SSMS.

Обязательные столбцы по заданию:

| Столбец | Содержимое |
|---|---|
| `SerialNumber` | Серийный номер сертификата, уникальный |
| `InsertedAt` | Дата и время внесения |
| `UpdatedAt` | Дата и время обновления (при первой записи равно `InsertedAt`) |
| `OwnerName` | Имя владельца — ФИО (из SN + G, иначе из CN) |
| `CertificationAuthority` | Удостоверяющий центр — полное имя издателя (`CN=…, O=…, C=RU`) |
| `CryptoProLicenseVersion` | Версия КриптоПро CSP, если в сертификат встроена лицензия |
| `HasEmbeddedCryptoProLicense` | Встроена ли лицензия КриптоПро в сертификат |

Пометка пропавших сертификатов:

| Столбец | Содержимое |
|---|---|
| `IsMissing` | 1 — сертификат не найден ни в одном месте, где был раньше |
| `MissingSince` | С какого сканирования не находится |
| `LastSeenAt` | Когда последний раз найден |

Место считается проверенным, только если оно входило в это сканирование: папка просматривалась, файлы с таким расширением искались, хранилища или контейнеры проверялись. Если в этот раз папку не смотрели, отметка не ставится. Если сертификат снова найден, отметка снимается. Истёкшие сертификаты вносятся и подсвечиваются красным, пропавшие показываются серым курсивом.

Сведения о КриптоПро на ПК: `InstalledCryptoProVersion`, `InstalledCryptoProLicenseSerial` (серийный номер лицензии, замаскирован), `InstalledCryptoProLicenseValidity` (срок действия лицензии).

Дополнительные столбцы: отпечаток, срок действия сертификата, ИНН, СНИЛС, ОГРН, организация, должность, DN субъекта и издателя, алгоритм подписи, ПК, где найден сертификат, способ сканирования.

Таблица мест `SkziCertificatesLocations` хранит связь «сертификат — ПК — файл, хранилище или контейнер» с датами первого и последнего обнаружения. На вкладке «Сертификаты в БД» по ней строится столбец «Сейчас есть на ПК».

## Безопасность

- Запросы и ответы агента подписываются HMAC-SHA256 общим ключом. Используется одноразовое число (nonce) и проверка времени запроса. Сам ключ по сети не передаётся.
- Агент может принимать запросы только с заданных адресов (`AllowedClients`).
- Пароль SQL хранится зашифрованным (DPAPI).
- Все SQL-запросы параметризованы. Имя таблицы проверяется по белому списку символов.
- Агент передаёт только открытые части сертификатов, закрытые ключи не читаются. Сертификаты из контейнеров КриптоПро запрашиваются у CSP штатно (CryptoAPI, `KP_CERTIFICATE`), без PIN-кода и без доступа к файлам ключей.
- Файлы `.p12/.pfx` открываются только паролем, который ввёл оператор. Пароли хранятся под DPAPI и агентам не передаются.
- Служба агента скрыта от обычных пользователей ограниченным дескриптором безопасности; администратор и система видят и контролируют её полностью (см. «Незаметность для рядового пользователя»).

**Ключ по умолчанию `RedFlag-SKZI-ChangeMe` нужно заменить:** в панели «Настройки» → «Сгенерировать новый», затем переустановить агенты.

## Тесты

`build.cmd test` запускает 25 автотестов:
- формат журнала с уровнями, ротация и удаление старых файлов;
- ASN.1;
- форматы файлов и парсинг полей, в т.ч. файлы куратора и PKCS#12 с паролем;
- правило «что входило в область сканирования»;
- срок лицензии КриптоПро на ПК;
- контейнеры КриптоПро на ПК без CSP;
- маски путей, безагентные пути в обе стороны;
- полное сканирование тестовой папки;
- конфигурация и сериализация;
- протокол агента: верный и неверный ключ, поиск агента, поиск только в папках панели;
- режим запуска агента (без параметров — в фоне) и настоящий `SkziAgent.exe --background`: сразу возвращает управление, отвечает на порту, `--status` его видит, `--stop` останавливает. Если на ПК уже работает агент, этот тест пропускается;
- одинаковые параметры службы при локальной установке и при установке из панели по сети (имя, скрытие от пользователей);
- защита от SQL-инъекций в имени таблицы;
- диапазоны IP.

Ещё 3 теста MSSQL (всего 28) запускаются, если задана строка подключения:
- создание таблицы, повторная запись без дублей, сохранение `InsertedAt` и рост `UpdatedAt`;
- дополнение и расширение «старой» таблицы;
- отметка пропавших и вернувшихся сертификатов, таблица мест.

```bat
set SKZI_TEST_SQL=Server=localhost\SQLEXPRESS;Database=SkziTest;Integrated Security=true
build.cmd test
```

Тестовые данные:
- `samples/certs` — наши сертификаты: DER, PEM в папке с кириллицей, PEM-цепочка, Base64 без заголовков, PKCS#7 с дублями, истёкший, лицензии КриптоПро 5.0, 4.0 и без версии, битый файл;
- `samples/curator` — файлы куратора: сертификаты Иванова и Петрова (`.cer`) и они же с закрытым ключом (`.p12`, пароль `changeit`);
- `samples/pkcs12` — наш `.p12` с паролем `RedFlag-2026` для проверки чтения с паролем.

Пересоздать наши файлы можно командой `bash samples/make_test_certs.sh` (нужен OpenSSL 3.4+).
